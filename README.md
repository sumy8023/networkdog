# networkdog

单实例 Windows 网络看门狗：盯住你的**主网口**，一旦主线路断电、断网或网线被拔，而机器还有第二条线路能上网时，立刻通过 [PushPlus](https://www.pushplus.plus/) 把告警推到你的微信。

## 它解决什么问题

机房、NAS、软路由这类机器常见的一种尴尬：**网断了，机器自己却不知道**。

- 光猫或主宽带掉电 → 整机失联，你只能等人到场才发现；
- 机器插了第二路上网（4G/USB 网卡/另一条宽带）时，Windows 会把默认路由自动漂到备用口，机器依旧"在线"，于是异常被彻底掩盖。

networkdog 反过来利用这一点：以最低跃点数默认路由的网关作为主网口标识，一旦这个标识消失或改变，就说明主口已经掉了——趁备用线路还能用，把消息发出去。

## 工作原理

启动时执行 `route print 0.0.0.0`，取跃点数（metric）最小的那条默认路由的**网关地址**记为主网口标识；之后每 5 秒复检一次：

| 状态 | 判定条件 | 动作 |
| --- | --- | --- |
| 💚 正常 | 默认路由仍是主网关，且 `ping 223.5.5.5` 通 | 重置计数 |
| 🔌 主网口物理断开 | 默认路由已漂到别的网关，且 `ipconfig` 中再也找不到主网关 | **立即推送** |
| ❌ 主网口外网中断 | 默认路由仍是主网关，但 ping 不通，**累计 3 轮（约 15 秒）** | **立即推送** |
| ⚠️ 其他异常 | 例如路由漂走但主网关仍在（手动改过跃点数等） | 只记录 |

推送成功后进入 **1 小时冷却**，避免断线期间反复轰炸微信。告警正文会附一个 6 位随机码，用于确认消息没有重复或丢失。

检测全部在本地完成（`route` / `ipconfig` / `ping`），不向任何第三方上报机器信息。

## 使用

1. 从 [Releases](../../releases) 下载 `server.exe`，放到任意目录（无需安装，无运行时依赖）。
2. 把同目录下的 `config.example.json` 复制为 `config.json`，填入你自己的 PushPlus token：

   ```json
   {
     "pushplusToken": "你的token"
   }
   ```

   token 在 PushPlus 官网"发送消息"页扫码获取。
3. 双击运行 `server.exe`，或在命令行里跑：

   ```
   .\server.exe
   ```

未配置 token 时程序照常监控，只在控制台记录异常、不发推送，并在启动时给出提示。

> `config.json` 请在 `.gitignore` 里排除好，不要连同 token 一起提交或分享。

### 作为服务常驻

用任务计划程序（`schtasks`）建一个开机启动、用户未登录时也运行的任务即可，程序本身会常驻前台循环，无需额外守护。

## 从源码运行 / 打包

```bash
node server.js          # 直接运行
npm run build           # 用 pkg 打包成单文件 exe（node18-win-x64）
```

打包需要 `pkg`（`npm i -g pkg`）。注意 pkg 生成的 exe 内嵌的是可读源码，token 来自同级 `config.json`，因此不会进入二进制。

## 运行环境

- Windows（判定依赖中文/英文 Windows 下 `route`、`ipconfig`、`ping` 的输出格式）
- 需要至少两路上网线路才有告警意义：主口掉电后，机器得有一条还能出网的备用线路
- 零 npm 运行时依赖

## 已知局限

- 主网口靠"最低跃点数默认路由的网关"识别。若你在同网段手动调整过跃点数、或两条线路网关相同，判定会失真。
- 备用线路必须走**物理上独立**的上行，否则主线路整体掉电时备用口也一起断，消息发不出去。
- `ping 223.5.5.5` 只代表外网可达，不能区分"运营商故障"和"本机防火墙拦截 ICMP"。
